02 / RUN A MODEL

Private AI.
From anywhere.

Run a supported model on a GPU you own or rent.
Connect to it from your laptop with the Hellas node.

  1. Serve Qwen on your GPU

    Install the CLI on both machines first. On the Linux GPU host, start a Hellas node with Docker, then tell it which model to serve.

    Download Qwen and start the node

    On the GPU host, download the pinned Qwen3-0.6B weights (1.2 GB).

    mkdir -p ~/hellas-demo/models
cd ~/hellas-demo
curl -fL -o models/qwen3.gguf \
  https://huggingface.co/unsloth/Qwen3-0.6B-GGUF/resolve/50968a4468ef4233ed78cd7c3de230dd1d61a56b/Qwen3-0.6B-BF16.gguf

    Choose one command for your GPU. Use a Linux x86_64 host with its GPU driver and Docker GPU access configured.

    NVIDIA · CUDA with NVIDIA CDI

    docker run -d --name hellas --network host \
  --device nvidia.com/gpu=all \
  -v hellas-state:/var/lib/hellas \
  -v "$PWD/models:$PWD/models:ro" \
  ghcr.io/hellas-ai/hellas:cuda

    AMD · ROCm

    docker run -d --name hellas --network host \
  --device /dev/kfd --device /dev/dri \
  -v hellas-state:/var/lib/hellas \
  -v "$PWD/models:$PWD/models:ro" \
  ghcr.io/hellas-ai/hellas:hip

    Read the fresh node’s invite from its logs. On the GPU host, replace the quoted placeholder with the complete invite.

    docker logs hellas
hellas pair 'PASTE_HELLAS_INVITE_HERE' --name mine

    From ~/hellas-demo on the GPU host, add the route and check that qwen3 is up.

    hellas route add "$PWD/models/qwen3.gguf"
hellas routes

  2. Connect from your laptop

    Give your laptop access to this model. The weights stay on the GPU host. Your laptop uses a small model descriptor to prepare each request.

    Pair the laptop and copy the descriptor

    On the laptop, print your contact.

    hellas contact

    On the GPU host, paste the full contact string to grant ten requests for one day.

    cd ~/hellas-demo
hellas share --to 'PASTE_HELLAS_CONTACT_HERE' \
  --resource qwen3 --limit requests:total:10 \
  --expires 1d --out laptop.access
hellas model describe models/qwen3.gguf -o qwen3

    Back on the laptop, replace user@host with your GPU host’s SSH login. Copy the access file and descriptor, then import the grant.

    gpu_host='user@host'
mkdir -p ~/hellas-demo
cd ~/hellas-demo
scp "${gpu_host}:hellas-demo/laptop.access" .
scp -r "${gpu_host}:hellas-demo/qwen3" .
hellas pair laptop.access --name gpu

    From ~/hellas-demo on the laptop, start the API. Leave this terminal running.

    hellas gateway --model ./qwen3@gpu \
  --bearer-file "$HOME/.hellas/qwen3.bearer"

  3. Talk to your model

    In a second laptop terminal, send a chat request. Look for Qwen’s reply in choices[0].message.content.

    curl -fsS http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer $(cat ~/.hellas/qwen3.bearer)" \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3","messages":[{"role":"user","content":"Say hello."}]}'
    Connect the Pi agent

    With Pi installed, add this provider to ~/.pi/agent/models.json. If the file already exists, merge the hellas entry into its providers object.

    {
  "providers": {
    "hellas": {
      "baseUrl": "http://127.0.0.1:8080/v1",
      "api": "openai-completions",
      "apiKey": "!cat ~/.hellas/qwen3.bearer",
      "models": [{"id": "qwen3", "maxTokens": 128}]
    }
  }
}
    pi --provider hellas --model qwen3
    Install Pi ↗

Install the Hellas CLI

Run on both the laptop and the GPU host. The client supports Apple silicon Macs and Linux on x86_64 or ARM64.

curl -fsSL https://github.com/hellas-ai/hellas/releases/latest/download/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
hellas --version

The installer puts hellas in ~/.local/bin. Add that directory to your shell profile to use it in new terminals.

Independent providers compete to run the program you specify.
Providers that already have the model in memory can start immediately.

Bring your own model or use secure fetch to call a hosted model API.

You and a provider agree on the job and price.

If anyone can run it, how do you check the result?

A fixed Catena program has one exact result for the agreed inputs. If the client disputes a signed result, the two sides can narrow the disagreement to a single step. The protocol design uses a fraud proof to settle the dispute against the provider’s stake.
